Program Structure and Design of the TCPConnection:
[The TCPConnection integrates the TCPReceiver and the TCPSender. 
In the TCPConnection class, there are two important method: 
segment_received and tick

segment_received:
The segment_received method is responsible for interpreting the state of the received TCP segment and appropriately routing it to the receiver and sender.

First, when a packet arrives, it resets _time_since_last_recv to 0 to record that the connection is alive. If an abnormal packet with the RST flag set is received, it transitions both streams (stream_in and stream_out) to an error state and terminates the connection.

Normal packets are passed to the receiver for data reassembly. If the peer sends a termination signal first while our side has not yet finished transmitting, this is considered a passive close, so it does not wait (linger).

If the received segment has the ACK flag set, it is forwarded to the sender to update the ackno and the peer's remaining window size. At this point, if there is no data to send, it generates and sends an empty segment. Furthermore, if the sequence number is ackno - 1, this is treated as a keep-alive request, and an empty segment is sent in this case as well.

Finally, it calls the push_segments_out() helper function, which sets the ackno and window_size on the segments generated by the sender and dispatches them to the network.

tick:
The tick method serves as the main timer for the TCP connection. When called with the time elapsed since its last invocation, it forwards this value to the sender's timer and increments the time passed since the last packet was received (_time_since_last_recv).

If the number of consecutive retransmissions exceeds the maximum limit (MAX_RETX_ATTEMPTS), the connection is forcefully aborted. In this scenario, both streams are put into an error state, and the sender is forced to generate and transmit a segment with the RST flag set.

Next, the method evaluates three prerequisites for a clean shutdown:

Has the incoming stream been fully reassembled and ended? (_receiver.stream_out().input_ended())

Has the outgoing stream been fully sent, including the FIN flag?

Has the outgoing stream been fully acknowledged by the peer? (_sender.bytes_in_flight() == 0)

If all three conditions are met, the connection termination is handled in two ways:

If lingering is not required (_linger_after_streams_finish == false), the connection is immediately deactivated (_active = false).

If lingering is required, the connection is kept active until the elapsed time since the last received packet reaches 10 * _cfg.rt_timeout, after which it is safely deactivated.

Finally, the method calls push_segments_out() to dispatch any pending segments to the network before returning.
]
